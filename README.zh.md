# dsh-sidebar-entry-manager

给 DSH 左侧导航栏的插件入口加一个开关。

DSH 的侧栏外壳只负责把 `sidebar.panellist` 里的注册项画成一行行，自带**没有**「单条入口隐藏」的设置，官方「更多」菜单也明确不放 Pin / 显隐操作。想少一行，通常只能把整个插件停用——功能也跟着没了。

这个插件补上那一步：**只隐藏那一行，插件照常运行**。

## 装好之后

**左侧栏底部齿轮 → 设置 → 侧边栏入口**

页面按当前真实注册情况列出所有侧栏入口（装了什么插件就显示什么，不写死），每行一个**开关**：

- 关掉 → 左侧导航里那一行不再画出来（收起成图标轨道时同样不显示）；
- 打开 → 立刻回来；
- 「全部恢复显示」一键还原。

选择保存在 Host 上（`~/.dsh/sidebar-entry-manager.json`），换端口、重启 DSH、换浏览器都还在。

## 插件更新（v0.2.0）

同一个设置页底部有「插件更新」：

- 显示当前版本，进页面时**静默检查**一次，也可手动点「检查更新」；
- 有新版本 → 「立即更新」走插件市场的公开更新 API（`/dsh-market/api/v1/*`）：市场负责装包、校验版本、保留回滚点；
- **自动更新**开关（默认关）：打开后，启动时发现新版本会自动安装；有会话在跑时市场会拒绝，插件不会强行更新，只提示稍后再试；
- 更新完成按市场返回的 `refreshRequired` / `restartRequired` 提示「刷新页面」或「重启 App」。

## 它到底改了什么

只改**导航行的绘制**：给那一行加 `display:none`，React 仍然持有该节点，插件、它的页面、它的快捷键、它注册的服务全都不受影响。

这不是「禁用插件」的替代品——要省资源请去插件页停用；要的是「东西还在，只是别占我侧栏」。

## 一个提醒

`plugins`（插件管理入口）也可以隐藏，但隐藏后侧栏里就没有插件管理的入口了。设置页本身不受影响，所以永远能从这里恢复。

## 已知边界

- 只管理根作用域的全局面板入口（`sidebar.panellist`）。右侧「侧边卡片」的标签页显隐是 `dsh-better-sidebar` 自己的「侧边卡片」设置页，两边互不覆盖。
- 侧栏末尾的「更多」按钮不是注册项，但它也会作为一行「「更多」菜单（宿主自带）」出现在设置里，可以单独隐藏；隐藏后插件市场的入口（浏览插件 / 创建插件）也一起收起，需要时再打开。
- 入口行是外壳画的，没有 id 属性，所以本插件按「声明顺序 + aria-label 校准」把 DOM 行对回注册 id。若某个插件给两行起了同一个名字且顺序也变了，可能认错——此时关掉再打开一次即可复位。
- 「插件」这一条的 id 是 `plugins`，`dshmarket` 的市场行是 `dsh-market`，两者互不相干。
- 自动更新依赖插件市场（dshmarket）的公开更新 API；没有市场时只能提示手动更新。

## 安装

```powershell
# 本地 tarball
dsh plugin --profile desktop add "<绝对路径>\dsh-sidebar-entry-manager-0.2.1.tgz"
```

也可以在 **插件 → 添加插件** 里填包名（发布到 npm 之后）。

## 开发

```powershell
node scripts/build.mjs   # src/ → lib/（浏览器半侧包一层 __ModuleLoader__ 信封，并注入版本号）
node --test              # 25 个用例，零依赖
```

- `src/host.js` → `lib/index.js`：状态文件（`hidden` + `autoUpdate`）+ 一条受信任围栏保护的 `/api/dsh-sidebar-entry-manager/state` 路由（GET 读 / POST 写）。
- `src/client.js` → `lib/client.js`：DOM 显隐 + 设置页分区（`settings.section`）+ 更新面板。
